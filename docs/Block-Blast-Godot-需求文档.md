## 0. 评审结论先行

第一版做成“无时间限制、单局无尽、拖放方块、填满行或列即消除”的纯规则益智游戏。Windows 版本先用鼠标完成完整闭环，触控只保留后续接入所需的输入抽象。棋盘、方块形状、计分、随机种子和本轮可解性检查都做成可配置或可测试的规则层，后续可替换主题、增加模式和接入排行榜。

用户已确认本轮实现基线：8×8 棋盘、空棋盘开局、每轮三块、3–5 格形状、不旋转、放置即按格数得基础分且清除另行加分、未清除落子重置连击、主菜单/暂停/重新开始/最高分全部进入 MVP。生成器必须保证新一轮至少存在一种允许玩家自由选择三块顺序、最终放完三块的合法方案；玩家操作后，若剩余方块全部没有合法落点，才进入 Game Over。

以上为第一阶段的历史基线，现在命名为“自由模式”。第二阶段美术与第三阶段三模式扩展见补充文档；第 13 节为 2026-10-14 的新增要求，扩展经典预置棋盘与闯关目标，不将下文原 MVP 的“单一无尽模式”和暂不纳入关卡地图继续视为当前产品范围。第 15 节记录用户于 2026-10-15 允许仅闯关第 1、2 关必要时使用 1–2 格救援的局部例外，其他模式与第 3 关起仍使用普通 3–5 格规则。

## 1. 产品目标与范围

### 1.1 目标

- 让玩家在 10 秒内理解“拖一个形状到棋盘，填满行/列并消除”的规则。
- 单局操作无倒计时，重点是空间规划、连消和“再来一局”循环。
- 每次放置都有清晰的吸附、消除、得分和连击反馈。
- 在 1280×720、1920×1080 和窄窗口中保持棋盘为正方形、可操作且不被 UI 遮挡。
- 发布包可在没有 Godot 编辑器的 Windows 机器启动，最高分和设置可安全保存。

### 1.2 MVP 范围

- 主菜单：开始游戏、最高分、设置、退出。
- 单一无尽模式：一个棋盘、三块待放方块、用完后补充下一组三块。
- 预定义 3–5 格方块形状；形状方向暂不在局内旋转。
- 鼠标拖放、非法位置回弹、合法位置吸附。
- 同时清除完整行和完整列；不下落、不重排剩余方块。
- 分数、连击、当前局结束面板、重新开始。
- 最高分及基础设置持久化。
- 基础动画、音效开关和键盘可操作的菜单按钮。

### 1.3 暂不纳入

- 联机、账号、云存档、排行榜服务和广告。
- 付费道具、体力、关卡地图和强制时间限制。
- 复制参考站或原作的 Logo、字体、音效、贴图、文案和品牌名称。
- 复杂特效、粒子堆叠、皮肤商店；这些属于后续内容更新。

## 2. 参考玩法分析

### 2.1 参考页面明确写出的内容

| 项目 | 页面明示内容 | 对本项目的处理 |
|---|---|---|
| 核心操作 | 将彩色方块拖放到网格 | MVP 必须支持 Windows 鼠标拖放；触控后续复用同一输入抽象 |
| 方块组成 | 每个方块由 3–5 个正方形组成 | 形状数据用格坐标保存，MVP 默认 3–5 格 |
| 消除条件 | 填满一行或一列后消除 | 行、列在一次落子结算中同时扫描并清除 |
| 得分 | 合法放置按放置格数得基础分，清除格数另行加分；同时清除多条线时清除部分有倍率 | 采用可配置的放置基础分、清除基础分和连击公式，见第 5 节 |
| 回合循环 | 放置方块 → 消除 → 获得空间 → 继续 | 三块耗尽后生成下一组三块 |
| 结束描述 | “没有可放置位置”时结束；页面另有“溢出/到顶”措辞 | 采用无合法放置作为唯一结束条件；无重力，不使用到顶规则 |
| 平台 | 页面宣称支持 PC 与手机浏览器 | Windows 优先；移动端作为响应式与触控扩展验收项 |

### 2.2 未被页面可靠确认的规则

以下内容页面未给出足够规格，不能直接当作事实：

- 棋盘是 8×8 还是其他尺寸。
- 开局棋盘是否预先有方块、初始布局是什么。

- 玩家是否能旋转、翻转方块，或只能放置预制方向。

目标页把游戏放在 iframe 中，当前可访问到的是落地页文案，无法可靠读取嵌入游戏的运行时画面和输入事件。因此本文没有把网格尺寸、托盘数量、精确倍率、旋转控件、非法放置反馈、暂停/重开、音效等写成“参考游戏已验证事实”。实现前应由开发者在本地可访问的运行版本中补做一次观察，并把确认结果回填到第 11 节。

## 3. 玩家流程

```text
启动
  → 主菜单
  → 开始游戏
  → 生成/加载棋盘与三块待放方块
  → 选中一块并拖到棋盘
       ├─ 非法位置：提示冲突并回弹，局面不变
       └─ 合法位置：吸附落子 → 同时扫描行/列 → 动画/得分/连击
  → 三块是否用完？是 → 生成下一组三块
  → 当前剩余方块是否全部无合法落点？是 → 游戏结束
  → 继续放置
```

暂停、重新开始和返回主菜单都必须明确提示，避免误触造成丢局。游戏结束面板展示本局分数、最高分、消除行列统计和“再来一局”。

## 4. 功能需求

### 4.1 主菜单与局外功能

**FR-MENU-01** 启动后显示游戏名称、开始按钮、最高分、设置按钮和退出按钮。  
**FR-MENU-02** 开始按钮进入新局；新局清空棋盘、分数、连击和当前方块。  
**FR-MENU-03** 设置至少包含音效开关、音乐开关和减少动画开关。  
**FR-MENU-04** 最高分在成功落盘后保留，损坏或版本不兼容时回退默认值，不阻止开始游戏。  
**FR-MENU-05** 所有按钮有悬停、按下、键盘聚焦和禁用状态；菜单按钮点击热区不小于 44×44 px。

### 4.2 棋盘

**FR-BOARD-01** 棋盘为 8×8，尺寸仍必须来自规则配置，不得散落在视图脚本常量中。  
**FR-BOARD-02** 每个格子只有空和已占用两种逻辑状态；已占用格保存颜色/主题索引，不参与碰撞物理。  
**FR-BOARD-03** 棋盘保持正方形，格子之间有统一间距；棋盘边界和落子高亮可见。  
**FR-BOARD-04** 新局初始棋盘全空。参考页面关于“开局已有方块”的描述不作为本版本规则。  
**FR-BOARD-05** 不使用重力，清除后剩余方块原位保留。

### 4.3 方块与生成

**FR-PIECE-01** 方块由一组局部坐标组成，例如 `[(0,0), (1,0), (0,1)]`；数据与显示节点分离。  
**FR-PIECE-02** MVP 形状覆盖直线、L、T、方块等常见类别；每种形状必须由 3–5 格组成，形状池和方向由配置管理。  
**FR-PIECE-03** 每局一次展示三块；三块全部被放置后才生成下一组三块。  
**FR-PIECE-04** 生成器使用可注入的随机种子；测试和问题复现能够记录并重播 seed。  
**FR-PIECE-05** MVP 不提供旋转按钮；若后续启用旋转，旋转必须先生成预览并重新执行边界/重叠校验。  
**FR-PIECE-06** 每次生成新一组三块前，生成器必须运行本轮可解性检查：在当前棋盘上枚举三块的任意排列顺序和每一步的所有合法位置，并模拟放置与行列清除；候选组必须至少存在一种允许玩家自由选择顺序、最终放完三块的方案，允许只有唯一解，也允许存在多解。没有解的候选组必须拒绝并重新生成。  
**FR-PIECE-07** 可解性检查使用与正式游戏完全相同的规则函数，不能使用简化的“只看当前能否放下”判断；固定 RNG seed 时必须得到可复现的方块组和可行顺序/落点路径。  
**FR-PIECE-08** 若随机重试达到配置上限，生成器使用预先验证过的保底方块组，并记录 seed 和失败原因，不能把无解方块组交给玩家。

### 4.4 拖放与落子

**FR-INPUT-01** 鼠标按下待放方块后进入拖动状态，拖动预览跟随指针并显示目标占用格。  
**FR-INPUT-02** 预览位置按棋盘局部坐标取整；合法时显示可落子颜色，越界或重叠时显示不可落子颜色。  
**FR-INPUT-03** 在合法位置释放后一次性写入整个形状，再进入消除结算；不能只写入部分格子。  
**FR-INPUT-04** 在棋盘外释放、越界、与已有方块重叠时，棋盘和分数不变，方块以 150–250 ms 动画回弹到托盘。  
**FR-INPUT-05** 第一版只要求 Windows 鼠标拖放正常运行；输入层预留 `InputEventScreenTouch` / `InputEventScreenDrag` 接口，后续接入触控时复用同一棋盘局部坐标映射。  
**FR-INPUT-06** 暂停、弹窗和菜单控件优先消费输入，棋盘不会穿透弹窗响应。

### 4.5 消除、得分与连击

**FR-CLEAR-01** 落子后同时检查完整行和完整列。行列的交叉格只计作一个被清除格。  
**FR-CLEAR-02** 同一次结算中清除多条线时，所有线一起进入清除动画，不产生先清一行再改变棋盘的顺序差异。  
**FR-CLEAR-03** 清除结束后不掉落、不移动其他方块；清除事件完成后才允许下一次落子。  
**FR-SCORE-01** 每次合法放置都立即获得放置基础分：`放置分 = 本次放置格数 × 10`；即使没有形成完整行或列，也必须加分。非法释放不产生放置分。
**FR-SCORE-02** 清除分在放置分之外额外计算：`清除分 = 清除格数量 × 10 × 清除线数倍率`。同次清除的线数为 `L` 时，清除部分倍率为 `1 + 0.5 × (L - 1)`；最终得分取整。
**FR-SCORE-03** 单次结算总得分为 `放置分 + 清除分`。例如，放置 3 格但未清除时得 `30` 分；放置 3 格并补满一条 8 格行时得 `30 + 80 = 110` 分。多线倍率只作用于清除分，不放大放置分。
**FR-SCORE-04** 连击在“连续两次有效落子都至少清除一条线”时递增；一次没有清除的有效落子仍将连击重置为 0。HUD 同时显示当前分、最高分、连击数、本次放置分、本次清除分和本次清除线数；得分跳字不遮挡棋盘。
**FR-SCORE-05** 放置基础分、清除分、清除线数倍率和连击重置时机都必须通过规则层测试覆盖，至少覆盖“无清除仍加放置分”和“放置分与清除分叠加”两种场景，不能只在动画脚本中计算。

### 4.6 游戏结束与恢复

**FR-END-01** 玩家可以从托盘中自由选择任意一块落子，不受托盘显示顺序限制。每次有效落子和清除结算后，检查剩余待放方块：只要其中任意一块存在合法落点，玩家就可以继续；只有当所有剩余方块都不存在合法落点时，才进入 Game Over。三块全部放完后，先生成并验证下一组三块，再继续游戏。  
**FR-END-02** Game Over 显示本局分数、最高分、总消除线数、重新开始和返回菜单。  
**FR-END-03** 暂停不改变逻辑状态；恢复后继续当前局。  
**FR-END-04** 重新开始必须二次确认或提供明显的撤销窗口，防止误触清空当前局。  
**FR-END-05** 退出到菜单时不默认保存正在进行的局；MVP 只保存最高分和设置。若评审需要断点续局，再增加版本化当前局存档。

## 5. 视觉与交互方向

参考方向采用明亮、彩色、玩具感的轻量 2D 风格：圆角方块、清晰边界、柔和阴影和短促的按下反馈。配色要让不同颜色易于区分，但颜色不能成为唯一信息来源；选中、不可放置和消除状态同时使用轮廓、亮度或图案变化。

建议设计基线：

- 背景使用低对比浅色或柔和渐变；棋盘表面与背景有明确层级。
- 方块使用 5–7 个主题色，色盲模式至少增加纹理/高光差异。
- 方块圆角 12–18 px，棋盘格间距保持一致；避免细碎装饰抢过棋盘。
- 悬停/按下/吸附/消除动画时长优先落在 150–300 ms；减少动画设置下仅保留必要状态变化。
- 使用矢量或 Godot 主题资源绘制 UI，不用 emoji 充当菜单图标。
- 文本和按钮对比度满足可读性要求；键盘焦点必须可见。

## 6. Godot 实现约束（需求级）

### 6.1 场景与模块建议

```text
Main.tscn
└─ Main (Control)
   ├─ ScreenRouter
   ├─ MainMenu (Control)
   └─ GameScreen (Control)
      ├─ HUD
      ├─ BoardView
      ├─ PieceTray
      ├─ DragLayer
      └─ Pause/GameOverModal
```

规则层建议拆成可独立测试的对象：`GameState`、`BoardRules`、`PieceGenerator`、`Scoring`、`SaveRepository`。显示层只订阅“落子、清除、得分、连击、结束”等事件，不直接修改规则状态；动画完成后由事件驱动下一步，避免视觉节点与逻辑棋盘不同步。

### 6.2 分辨率与坐标

当前工程已经设置 `window/stretch/mode="canvas_items"` 和 `window/stretch/aspect="expand"`。需求层继续使用 Control anchors/Containers 做布局：棋盘按可用区域的较小边计算格子尺寸，不能用固定像素硬编码棋盘位置。验收至少覆盖 1280×720、1920×1080、窄窗口和 720×1280 竖屏预览。

### 6.3 输入

棋盘输入可由 `Control._gui_input` 或根节点统一接收，必须把 Viewport 坐标转换为棋盘局部坐标后再计算行列。按钮需要正确处理 `mouse_filter` 和 `accept_event()`，保证弹窗出现时不穿透到棋盘。第一版只验收 Windows 鼠标；触控接口保留为后续输入适配层，不以“触控转鼠标”模拟替代正式触控实现。

### 6.4 配置与存档

- 形状表、棋盘尺寸、计分倍率和主题使用自定义 `Resource` / `.tres`，便于后续调参。
- 用户数据保存到 `user://savegame.json`（或等价的版本化二进制），绝不写入导出后的 `res://`。
- 存档至少包含版本号、最高分、设置和可选 RNG seed；读取失败或版本不兼容时安全回退默认值。

### 6.5 渲染与 Windows 导出

当前项目强制 Windows D3D12 / Forward Plus，第一版保持该配置，以 Godot 编辑器中能正常运行和 Windows x86_64 导出为目标。后续若扩大硬件覆盖，再单独评估 Compatibility 渲染器。首版导出建议 Windows x86_64 release，安装匹配 Godot 4.7.2 的 export templates，并提供 debug 与 release 两个预设。验收包含无编辑器机器启动、图标、版本号和存档写入。

## 7. 验收标准

### 7.1 核心规则验收

- [ ] 新局打开后可看到棋盘、分数和三块待放方块。
- [ ] 合法形状完整落子；边界、越界、重叠均有明确预览。
- [ ] 非法释放会回弹，棋盘、分数、连击均不变。
- [ ] 完整行、完整列、行列同时完成都能一次性正确清除。
- [ ] 行列交叉格只计算一次，剩余方块不下落。
- [ ] 三块用完后才补充下一组三块，托盘不会重复消费或漏消费。
- [ ] 新生成的一组三块至少存在一种可自由选择顺序、最终放完三块的合法方案；唯一解和多解都可接受。
- [ ] 每次合法放置按放置格数加基础分；无清除的 3 格落子得 30 分。
- [ ] 放置分与清除分额外叠加；3 格补满一条 8 格行时得 30 + 80 = 110 分，多线倍率只作用于清除分。
- [ ] 得分、倍率、连击与规则公式一致，且动画期间不能重复落子。
- [ ] 玩家操作后，若剩余方块全部无合法落点才进入 Game Over；可重新开始并正确更新最高分。
- [ ] 暂停、恢复、返回菜单和设置开关行为可复现。

### 7.2 输入与布局验收

- [ ] 鼠标拖放在 1280×720、1920×1080、窄窗口下坐标一致。
- [ ] 第一版 Windows 鼠标拖放在 1280×720、1920×1080、窄窗口下坐标一致；触控接口不纳入本版通过条件。
- [ ] 720×1280 竖屏预览中棋盘仍为正方形，托盘、HUD、按钮不重叠。
- [ ] 弹窗打开时棋盘不接收穿透输入，键盘焦点顺序合理。

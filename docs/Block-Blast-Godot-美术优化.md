# Block 第二阶段美术优化（0.2.0）

更新：2026-10-14。

用户要求第一阶段逻辑开发到此为止，第二阶段转向 UI、方块、布局、消除反馈、加分效果、震动与提醒。当前源码版本为 `0.2.0`，请在 Godot 4.7.2 中按 F5 运行验收；本轮没有生成新的 Windows 发布包。

## 参考与范围

前三张参考图用于确定美术方向：蓝色渐变背景、藏蓝内凹棋盘、高饱和斜面方块、金色皇冠最高分、青色大号当前分，以及没有白色托盘卡片的独立待选方块。广告区域、手机状态栏和参考中的 NEW 标记不进入游戏。

最后提供的 WebP 实际只有一帧，尺寸为 288×640，只能核对静态画面，无法确认视频中的闪光、消除、加分飞行和震动时序。当前反馈是根据参考中的 Combo、光效与加分表现制作的可调版本，不能称为逐帧复现视频。

第一阶段规则冻结：8×8、每轮三块、3–5 格、不旋转、任意顺序可解生成、落子后无合法落点结束，以及放置分和额外清除分均沿用已确认逻辑。参考中的 `+1` 不覆盖本项目每格 ×10 的计分；本轮不调整形状池、生成搜索或结束判定。

| 项目 | 0.2.0 表现 |

## 提醒与消除反馈

- 拖动中的合法落点会将即将填满的整行/列显示为同一颜色：按本次落子后该线的颜色占格数选多数色，平票取该线中仍存在的最早落子颜色；预览、拖动浮层、消除块和碎片沿用同一结果。取消预览不改变实际格子颜色。非法释放继续回弹并提示，规则状态与分数不变。
- 多条平行线分别统计；行列相交时，按用户确认将所有相交行列整组去重后投票，交点只统计一次，全组使用同一颜色。颜色判定使用原格颜色和合法落子序号，不按颜色编号或格子位置推断先后。
- 托盘不提前标记方块能否放下：所有方块保持相同亮度，不显示“暂不能放”文字，也不在选中时提前提醒；玩家自行判断，非法释放后才反馈。
- 三块补充和本局首次刷新纪录使用非阻塞提示，不弹出需要确认的对话框。
- 合法落子轻弹，消除依次表现短闪光、行列扫光、缩散与彩色粒子，交叉格不会表现为重复消除。
- 加分浮字展示本次真实得分，并飞向 HUD 分数区域；连续消线连击至少为 2 时显示 Combo，多线消除也展示相应奖励提示。
- 棋盘可发生短促轻震，最大偏移 5px。震动只改变视觉偏移，不移动控件或改变合法落点与鼠标坐标判定。
- 暂停与失焦冻结反馈；重开、返回菜单或窗口调整清理视觉状态；输入锁随棋盘反馈结束释放。

Windows 本轮仅实现棋盘视觉震动，没有接入鼠标、手柄或手机的硬件振动。

## 设置与兼容

设置新增“画面震动”，保存字段为 `screen_shake`。存档仍使用 `version: 1`，历史存档缺少该字段时使用默认值，已有最高分、音效、音乐与减少动画设置保留。当前没有新增进行中棋局的断点保存。

开启“减少动画”时关闭分数飞行、粒子和画面震动，反馈采用简化显示；计分、消除、生成和游戏结束结果不受影响。“画面震动”开关只影响震动，音效与音乐仍使用原来的独立开关。

反馈基础时长与色板由 `config/default_rules.tres` 管理，材质与矢量图标由 `scripts/ui/block_art.gd` 统一绘制；后续可根据用户观感调整节奏、亮度、粒子密度和震动幅度。

当前默认落子 0.12 秒、清除 0.32 秒（亮闪 0.06 秒、扫光 0.10 秒、缩散 0.16 秒），棋盘反馈输入锁合计约 0.44 秒、最多 0.50 秒。粒子与连击提示约 0.62 秒，加分飞行约 0.68 秒；后续余效不会延长落子锁。

## 用户验收顺序

1. 停止旧游戏，在 Godot 中按 F5，确认蓝色主菜单、设置与开始按钮显示正常；进入游戏核对中央棋盘、六色斜面方块、皇冠与大号分数。
2. 拖动方块，核对托盘、浮层和棋盘材质一致，抓取锚点正确；预览填满行列时出现高亮，非法释放仍回弹。
3. 预览单线或平行多线，确认每条线按多数色统一，平票由最早放置的颜色胜出；交叉行列按去重后的整组主色统一。实际落子后的消除动画应沿用预览色。观察闪光、扫光、粒子、加分飞行与轻震；连续消线时观察 Combo。分数仍按真实结算增加。
4. 核对补充三块、首次新纪录提示不阻挡操作，提示面板与棋盘及托盘之间有明显间距；托盘不出现可放性文字或变暗，选中方块不提前提醒，非法释放后才提示。
5. 游戏中打开齿轮设置并返回，确认棋局保留；动画中暂停/失焦后恢复，重开和返回菜单无残留；暂停与 Game Over 卡片的标题、统计与按钮完整显示。
6. 分别关闭画面震动、开启减少动画，确认反馈按设置变化；退出并重启后核对新开关与原有记录保存。检查 1280×720、1920×1080 和窄窗口下布局及鼠标命中一致。

本轮由用户验收实际观感和操作，不自动控制桌面、不执行 GUI 点击/拖动或完整自动验收。集成阶段的轻量语法/编译证据记录在 [验收记录](Block-Blast-Godot-验收记录.md)，编译通过不能代替视觉或运行验收。

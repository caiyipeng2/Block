# Block 三种模式说明

更新：2026-10-15；源码版本：`0.6.9`。本文件记录当前代码目标与用户验收口径，不能作为运行验收通过结论。本轮增加逐关失败重试辅助，保留 CSV 原有参数、目标、解锁记录和界面反馈；仅真实 Game Over 累计，下一局生效。

## 模式与共同规则

| 模式 | 开局 | 结束与记录 |
|---|---|---|
| 自由 | 原有 8×8 空棋盘 | 无积分上限；无合法落点时结束；沿用旧版最高分 |
| 经典 | 每局按种子随机预置约 16–24 格，保留空格、不生成满行/列 | 无积分上限；无合法落点时结束；独立最高分 |
| 闯关 | 读取每关种子与开局参数；前两关分数教学，第 3 关起为图案棋盘、携带标记托盘与 1–4 类配额 | 各类配额全部归零通关；无合法落点时失败，前两关保留局部救援；保存逐关进度与最佳分 |

三种模式保留每轮三块、不旋转、任意放置顺序、行列同时清除、交叉格只清一次、不下落。自由、经典与前两关普通块保持 3–5 格，前两关必要时允许 1–2 格救援；收集模式另用私有 2–9 格池，包括横竖 2/3/4/5 格、2×3、3×2、3×3、斜三等，不改公共池。合法放置每个实际格 ×10，清除另行加分，多线倍率只作用于清除分；非法释放不加分，预置方块不计分或开场自动清线。没有新增倒计时、付费道具或提前可放性提示。

## 当前闯关目标

当前关数为 `ModeCatalog.MAX_LEVELS = 96`，配置表必须恰好包含连续的 1–96 关；不能仅追加第 97 行扩关。将来扩关还需同步代码与对应验收，不将参考图数字视作用户已确认的最终关数。

| 关卡 | 目标类型 | 达成条件 | HUD |
|---|---|---|---|
| 第 1 关 | 分数 | 达到表中 `target_score`，随附值 368 | 当前分数 → 配置目标 |
| 第 2 关 | 分数 | 达到表中 `target_score`，随附值 392 | 当前分数 → 配置目标 |
| 第 3–96 关 | 配额收集 | 蓝钻/金宝/黄星/红星分别读取数量，0 不参与，启用类型各自归零 | 1–4 类展示需求，每枚飞到后更新；计分明细在暂停 |

目标类型、数量、难度和开局参数唯一来源为 [`config/adventure_levels.csv`](../config/adventure_levels.csv)，由 `AdventureLevelTable` 校验、`ModeCatalog.objective_config()` 等接口统一提供。选关说明通过 `objective_description()` 与开场、HUD 读取同一行数据。第 3 关起 `target_score` 为 0，表示不使用分数作为通关条件，不能将 0 解释为开场自动通关。`0.3.0` 的全关目标分公式及“末关 3448 分”仅属于历史。

四种目标为蓝钻、金宝、黄星和红星，每种可独立填 0–999；收集关至少启用一种。可以配置一类、两类、三类或四类，也可以让相邻关目标数量高低交替，不再强制轮换、线性或阶梯增长。目标配额与物理标记数量分别管理：初始棋盘和托盘都可携带标记，新组持续供应尚未完成类型；已经存在的富余标记不会因需求完成而删除。

### 标记美术与数据传递

四类图案沿用暖砂金底托与柔和受光的统一绘制，在棋盘、托盘、拖动/回弹、预览、落地、清除、HUD 和飞行中保持类型一致。标记由 `PieceData.targets` 随方块传递，不因形状复制或取消拖动丢失；满线统一主色只改底块，目标最后单独叠加。

只有标记格被完整行/列真实清除才结算，交点只计一次；预览、非法释放不计。每类实际计入为 `min(本次清除该类数量, 该类剩余需求)`，不会负数或抵扣其他类型。需求只差 1 时仍可供多枚、清多枚；**本关启用的各类需求均为 0 即通关，富余物理标记允许留盘**，无需把所有标记清空。

## 自动收集介绍与胜利面板

第 3 关起自动展示本关启用的各类目标约 1.0 秒，约 0.48 秒飞入 HUD，再用约 0.70 秒填充/擦拭揭示棋盘。此流程纯显示，不触发额外落子、得分或清除，不伪造通过率。点击或按键可以跳过；减少动画时延后下一帧结束介绍，避免同步回调破坏输入状态。

介绍期间隔离棋盘拖放、普通游戏快捷键和背景焦点；跳过输入只完成介绍，不同时落子、暂停或重开。窗口变化与减少动画能结束显示并保留正确规则状态，重开和下一收集关会重新介绍。前两关保留旧分数教学流程，不套用本介绍。

胜利面板显示大号 `Well Done`、完成目标与绿勾、彩纸、绿色 `Next Level` 及次要操作。点击 `Next Level／下一关` 先回选关页，待解锁演出结束后由玩家手动点击开始新关；不直接进入下一局。最后一关无下一关入口。连胜系统、地图奖励明确不在本轮范围。

## 第 1、2 关的持续推进

首两关承担引导和吸引玩家继续游玩的作用。随附表的目标为 368、392 分，可逐关修改 `target_score` 与 `initial_fill`；不再以容易堵死的开局或托盘制造教学门槛。持续进行合法落子可以推进到配置目标，停留不操作不会自动完成目标。

- 生成托盘时，先按当前棋盘优先挑选利于清线的普通 3–5 格方块，并逐步构造能把整组全部放完的证书；不是只验证第一块能放下。
- 每次合法落子并结算行列清除后，重新检查剩余组的完整可放路径。仍有完整路径则保留原组；没有完整路径时，尽可能保留仍可用的组合，只替换为同样剩余数量的可解方块。已落棋盘不撤回、不挪动，动画结束后托盘须与新组一致。
- 构造认证路线的每一步，先在该步模拟棋盘上寻找普通 3–5 格合法点；普通形状全无合法点时才考虑 2 格，2 格也无合法点才用 1 格。因此一组托盘可以预先包含后续步骤必要的救援块，并不要求显示小块时当前真实棋盘上已经没有任何普通落点。该能力只在闯关模式的分数目标第 1、2 关内生效，不加入公共形状池，也不放宽其他模式的形状校验。
- 救援不赠送分数、不自动清除、不降低目标。只有玩家真正合法放置才按真实格数计分，清除仍额外结算；无效释放仍不加分。

默认 8×8、每格放置 10 分的配置下，行列清除结算后始终留下空格，必要的一格救援保留下一次合法落子的机会；每次合法落子至少得 10 分。因此使用随附 368/392 分目标时，从 0 分开始持续合法操作分别不超过 37、40 次合法落子可达到目标，实际通常因多格放置和清除更快。修改目标后上限随之改变；该结论依赖默认计分及上述局部救援规则，不能套用于自定义的 0 分配置、第 3 关起或其他模式。

第 3 关起的收集目标、自由模式、经典模式不使用该救援或逐步修复，继续保留玩家选择导致失败的规则；不因此承诺玩家任意落子都能通过收集关。

## 开局认证与难度边界

关卡使用表中固定种子 `seed`，同一版本、配置、失败次数与操作下可复现生成；重试重读表，恢复当前配置的布局与完整需求，不沿用失败局收集数。收集图案由 `template_id` 选择 `wings`、`heart`、`ring`、`steps`、`butterfly`，`mirror` 控制镜像，`initial_markers` 单独控制初始特殊格数量，不等于整关配额。

前两关维持原教学生成和必要救援。第 3 关起改用收集私有形状池及持续标记供给，不再要求全部目标开局存在或整关最多三组认证。每组必须有完整合法放置证书；先尝试有限次清线友好构造，失败后回退完整求解器，不能只因第一块可放就接受整组。

后续组根据尚未完成的类型持续携带标记，已完成类型的旧富余标记保留；标记数量不必刚好等于配额。玩家选择仍可能导致所有剩余块无合法点而失败，**不保证任意错摆必过**，收集关不启用前两关教学救援。

### 失败后的下一局辅助（0.6.9）

每关独立累计失败，只有本局至少合法放置过一次、最终进入 Game Over 才计一次；单局重复显示结束界面不会重复记数。无效初始局、进行中主动重开、返回菜单、退出和暂停不计。失败次数立即尝试保存，最多保留 99 次；保存失败沿用“仅本次运行有效”提示。旧 version 1 存档兼容默认 0，不影响解锁、最佳分与设置。

第 3 关起，新开/重开取该关失败次数与表中的 `retry_assist_step`、`retry_assist_max`，辅助强度为 `min(失败次数 × 步长, 上限) / 100`，整局固定。默认 `20/60`：失败一次后为 20%、两次 40%、三次及以上 60%。两列支持 0–100 小数，任一为 0 关闭该关新增辅助；旧 15 列表缺列时兼容默认值，已存在列不可留空。前两关沿用教学救援，不叠加新增辅助；自由/经典不适用。

辅助会将有效供块难度调整为 `difficulty × (1 − 辅助强度)`，并独立增加仍欠目标、短小/更多落点和清后空间的候选权重；尚缺类型的标记更密集，并按剩余配额加权和轮换覆盖。`difficulty=0` 仍可得到目标与空间辅助。这些百分比是生成权重，不是通过率；仍使用原 2–9 格池与整组三块证书，不添加一格救援、不替换当前剩余托盘、不减少目标或更改计分，玩家仍可能失败。

通关清除该关失败记录，之后重玩恢复表中基线；其他关记录不变，失败不会连带降低下一关。当前局不因改表或累计记录中途变难度，界面不提示“已降低难度”。配表示例见 [关卡配表说明](Block-Blast-Godot-关卡配表说明.md)。

实际占用取决于模板及镜像，难度系数不会自动增加模板格数；`initial_markers` 允许为 0，但不能超过该模板实际占格。配额、初始特殊格数和难度可分别配置，不要求逐关递增或末关固定 43 格。修改棋盘、形状池或目标配置需重新验收，不能套用默认结论；模板不适配自定义棋盘时显式拒绝开局。

认证托盘完整可放不等于每关唯一或整关保证可过；有限搜索/计数截断也不能当作唯一证明。本版不承诺竞品算法复刻，实际难度和响应仍需游玩调校。

收集供块的 `difficulty_ratio` 直接取本关 `difficulty / 100`，`difficulty` 允许 0–100 的小数，收集关首组与后续组共用，不再按关号计算。清线始终最高优先；清线条件相同时，该比率控制合法落点数权重 +2→-4、格数权重 12→65：低值偏宽松落点，高值偏大块和较少落点。前两关的该值仅影响开局占格布局，后续仍按教学供块与必要救援处理，调高难度不会取消救援。难度文字使用 `difficulty_label`。这些是候选权重和展示标签，不是实机难度证明，也不保证唯一解或整关必胜。

### 配表编辑、重读与错误处理

用 Excel/WPS 编辑 [`config/adventure_levels.csv`](../config/adventure_levels.csv)，另存为“CSV UTF-8（逗号分隔）”，可带 BOM，保留原表头与连续 1–96 关。普通 CSV 可能为 GBK/GB18030，本版会拒绝非 UTF-8 并提示正确另存格式。各字段范围、模板和示例见 [关卡配表说明](Block-Blast-Godot-关卡配表说明.md)。进入选关、开始新局和重开时重新读取；正在进行的棋局继续使用开局快照，不被文件修改即时改写。

表头、整数/小数格式、范围、漏关/重复关或非法模板等任一错误都会使整表失败。界面给出 CSV 路径和行列原因，拒绝进入闯关且不回退旧公式，不清空已有局；自由/经典仍可进入。前两关只配置分数目标，第 3 关起只配置收集目标，不允许把两种通关条件混填。CSV 已配置保留原文导入和导出包含规则；本轮未导出新包。

## 反馈与减少动画

独立 `CollectionFlights` 管理收集飞行：标记先弹大、向外散开，再吸入对应 HUD；每枚到达才减少展示需求、闪光，完成时显示绿勾。规则计数与展示计数分离，末次弹窗必须等待最后飞行。下一次落子不删除旧批；暂停冻结，resize 或减少动画结清显示，新局静默重置旧飞行。

收集关关闭 `+分` 浮字，真实分数继续累计，明细在暂停查看；其他模式沿用原加分反馈。物理清除数与计入配额区分，配额不足时封顶不负数。减少动画取消粒子/飞行/震动并结清展示，地图标记静止；视觉轻震不是硬件震动。本轮已审阅用户的 `20261015-121221.mp4`（112.7 秒）完整时间线及关键 0.1–0.25 秒片段，按确认条目实现；不承诺逐帧复制，竞品音效和内部算法未知，实际观感仍由用户确认。

## 保存与兼容

# Block 三模式全球排行榜需求与 UI 提案

日期：2026-10-26；实施范围确认：2026-10-28。状态：**用户已确认方案，当前只实施排行榜客户端；后端环境在客户端完成后搭建**。

分期约定：后端采用 Firebase Authentication、Firestore 与 Cloud Run。当前客户端实现榜单、设备资料、本地记录/缓存/队列和 HTTPS 请求契约；真实 Google OAuth、账号绑定、云存档冲突恢复、服务端排名与对局回放校验属于后续联网阶段。未配置服务时不发请求，但客户端仍显示本地演示用的机器人榜单，避免排行榜页面空白；服务已配置且服务端返回的真实玩家数少于 100 时，客户端用带内部 `is_bot` 标记的机器人补齐展示位。以下完整需求保留为后续联网阶段基线。

依据：当前客户端实现基线 `cd8d838`（Block 0.9.5）、现有三模式规则、存档结构，以及菜单/设置真机截图。本轮未启动 Godot 界面。工作区中其他任务的代码改动保留，不属于此方案。

## 1. 已明确的用户选择

1. 全球联网排行榜，三种模式分别排名，设备账号可参榜。
2. 闯关先比较已通关关卡数，同关数比较各已通关关卡最佳分之和。
3. 旧版本已有的最高分和闯关进度直接带入全球榜，保持连续体验；旧存档无法严格验证这一边界保留。
4. 玩家可在设置中主动绑定 Google 账号，用于云端存档上传、跨设备恢复和排行榜账号找回；不强制绑定。
5. 先确认需求和最终 UI 效果，再开始开发。

以下未逐项单独询问的细节均为本次推荐方案，以最终确认作为实施基线。

## 2. 推荐首版范围

Windows 与 Android 共用同一榜单服务。提供全球永久总榜，不重置；包含三个模式页签、前三名、Top 100、我的排名、玩家昵称及预置头像、结算页快捷入口、旧成绩迁移、加载/空榜/离线/待同步状态、中英法文案。

首版暂不加入周榜、赛季、好友、地区筛选、奖励、聊天及其他社交平台登录。Google 账号绑定仅作为玩家主动选择的云存档与账号找回入口；它不改变设备 UID 的本地基础身份。

| 可选界面方式 | 优点 | 代价 | 取舍 |
|---|---|---|---|
| 一个排行榜页，三个模式页签 | 入口统一，可直接横向比较自己的三项成绩，界面与服务可复用 | 需要记忆进入来源和选中页签 | **推荐**，本次效果图采用 |
| 每个模式一个独立排行榜弹窗 | 每个模式都能放专属说明 | 入口分散，三套弹窗重复维护 | 备选 |
| 主菜单直接展示三张小榜卡 | 一眼看到三项个人排名 | 挤压已确认的菜单构图，长文本和小屏困难 | 不采用 |

## 3. 排名口径

| 模式 | 第一排序项 | 第二排序项 | 完全相同的名次 | 成绩更新 |
|---|---|---|---|---|
| 闯关 | 连续已通关关卡数，降序，目前 0–96 | 第 1 关至最高已通关关卡，各关最佳通关分之和，降序 | 并列 | 通关增加进度；重玩通关可以提高该关最佳分 |
| 经典 | 该模式单局最高分，降序 | 无 | 并列 | 新高才替换，低分不覆盖 |
| 自由 | 该模式单局最高分，降序 | 无 | 并列 | 新高才替换，低分不覆盖 |

- 每个玩家在每个榜单最多一条记录。三个模式不混分，不把经典分累加到自由分。
- 并列采用竞争排名，例如 1、2、2、4；分页内部可按稳定玩家 ID 保证顺序，但不以达到时间偷偷打破并列。
- 闯关按**已通过的关数**，不是最新解锁关卡、选择的关卡或进行中的关卡。例：已通关 42 关、解锁 43 关，榜单显示 42 关。
- 闯关总积分仅累加有通关记录的关卡；失败和未通关局的分数不加入。不把所有重玩分数累计，重玩只取对应关的最大值。
- 两个玩家都是 96 关，268,540 分优先于 251,800 分；95 关即使有 260,000 分，也排在 96 关之后。
- 新玩家没有有效成绩时显示“尚未上榜”，不伪造第 0 名。自由/经典取得正分、闯关至少通关 1 关后可形成记录。

### 3.1 不足 100 人时的机器人补位

- 服务端榜单响应必须返回 `real_player_count`。当真实玩家数小于 100，客户端将真实条目和机器人条目合并后按当前模式的正式排序规则重新排名，补齐到 100 个展示条目；真实玩家数达到或超过 100 时不生成机器人。
- 机器人只用于榜单展示，不进入成绩提交队列、旧档迁移、我的排名或任何服务端统计；条目带内部 `is_bot=true`，UI 不显示“机器人”标签，使用普通预置头像和自然的中文/英文昵称。
- 经典/自由机器人按最高分降序；闯关机器人按通关关卡数降序、再按已通关关卡最佳分总和降序。相同键使用竞争排名，真实玩家进入后自然占据合法排序位置并替换缺口机器人。
- 机器人昵称、头像、分数和排名每 30 分钟按确定性新周期变化；同一周期内刷新榜单不抖动，重启后同周期结果可复现。机器人分数不会超过当前真实玩家的最低合法位置，空榜时使用独立的渐进分数曲线。
- 客户端未配置榜单服务时显示离线状态和本地演示榜，明确不提供个人全球名次；收到合法榜单响应或缓存后，演示机器人由权威 `real_player_count` 控制并可被真实玩家替换。

## 4. 成绩记录和提交流程

### 4.1 新对局

- 自由/经典在正常结束、确认重开、确认离开时提交已取得的本局成绩，保留当前本机最高分的体验。只有服务端认可的新高才改变全球纪录；取消确认框不终结对局。
- 游戏过程中可按新高做节流检查点，减少异常退出丢失榜单成绩的机会。提交内容使用同一 run_id 和递增检查点序号，重试不重复创建记录。
- 闯关在逻辑通关后提交，画面上的庆祝和解锁无需等待网络。重复打开结算或重复补传都不增加通关数。
- 在线开始的对局取得服务端签发的对局凭据；新成绩校验通过后才显示新名次。校验期间显示“成绩同步中”，不显示推测名次。
- 中途断网继续游玩，提交记录进入本地持久队列，重连自动补传。完全离线开始的新局先保留为本机成绩；缺少服务端对局凭据时不冒充已验证全球成绩。可以继续玩游戏，无联网强制弹窗。

### 4.2 旧版成绩直接迁移

- 新版首次进入游戏时读取设备唯一标识并生成设备账号 UID；首次成功连接时为该 UID 一次性导入自由最高分、经典最高分、闯关已通关数及各已通关关卡最佳分。
- 导入保持原存档和解锁数据；不清档、不归零、不要求重打关卡或刷新旧高分。
- 服务端以迁移请求 ID 和设备账号 UID 保证幂等；网络重试不会多次累计。闯关总分由服务器逐关取最大值后求和，忽略最高已通关关卡之外的分数。
- 导入记录标记为 `legacy_import`，参与正式总榜；仅做类型、范围、版本及结构校验，不能宣称证明其原始对局真实。以后更新按新对局流程处理。
- 本次迁移只覆盖第一次接入时的历史快照；不能反复修改本机存档并以“历史迁移”重新提交新分数。

### 4.3 Google 绑定和云存档

- 未绑定 Google 时：设备 UID 仍是本机账号，游戏可以离线游玩；本机存档继续正常读写，全球榜需要联网同步。
- 玩家点击设置中的“绑定 Google 账号”后，使用 Google Sign-In/OpenID 完成授权；服务端把 Google 账号主体标识绑定到当前设备 UID，不把原始 Google 邮箱或设备 ID 作为公开账号字段。
- 绑定成功后，把当前设备 UID 关联到 Google OpenID subject，并上传当前存档快照、逐关最佳分、最高分和排行榜状态。服务端返回绑定关系及云存档版本号。
- 以后在新设备进入游戏：先生成该设备 UID；玩家在设置中主动绑定同一 Google 账号后，服务端找到已关联的游戏账号并提供云存档恢复，不自动覆盖当前本机存档。
- 首次绑定或恢复发现本机与云端都有进度时，显示冲突预览：本机进度、云端进度、三模式最高分、闯关通关数和最近更新时间。玩家选择“使用本机存档”或“使用云端存档”后才覆盖；不静默丢失任一份存档。
- 选择合并时只做安全合并：自由/经典最高分取较高值；闯关已通关关卡取并集，各关最佳分取较高值；语言、音效、音乐、减少动画等设置以当前设备为准；失败次数不跨设备累加。
- 解除绑定只解除 Google 与设备账号的关联，不删除云端存档；当前设备仍可用设备 UID 游玩。再次绑定其他 Google 账号必须经过确认和冲突预览。

## 5. 设备账号和玩家展示

- 首次进入游戏读取 `OS.get_unique_id()` 作为设备标识输入，生成版本化的设备账号 UID；原始设备标识不显示在 UI、不作为玩家昵称、不写入排行榜公开数据。服务端返回的 `account_id` 与 UID 绑定，UI 使用“玩家4821”一类的可编辑昵称。
- UID 生成采用项目命名空间和单向派生值，客户端保存 UID 与服务端会话凭据；设备标识变化时创建新 UID，不尝试把新设备伪装成旧账号。Android 首次启动仍需要网络权限才能同步全球榜。
- 点击“我的”行头像或昵称可编辑资料：昵称 2–12 个字符，支持中文、英文及法语重音，按 NFC 归一化；使用 6 个预置方块/星形头像。
- 初始昵称由设备账号随机生成，例如“玩家4821”；玩家之后可在设置中修改昵称。昵称与 UID 分离，改名不创建新账号、不影响榜单历史。
- 设置增加设备账号区：未绑定时显示“绑定 Google 账号”；绑定中显示进度；已绑定显示“Google 已绑定”和“管理绑定”；离线时允许继续游戏，但绑定操作显示“需要联网”。
- 公开列表只展示昵称、预置头像、名次、对应成绩；不展示原始设备标识、UID、凭据或真实身份。
- 本机保存设备账号 UID 和会话凭据。首版不承诺卸载、清除数据、换机或跨平台后找回同一个设备账号，也不把“共用全球榜”描述成“跨设备身份同步”。
- 设备标识不是安全凭据：Godot 官方说明设备唯一 ID 可能因重装系统、系统升级或硬件变化而改变，也可能被外部程序伪造，因此服务端仍需会话校验、成绩验证和限流；不得用它单独证明成绩真实性。参考：[Godot OS.get_unique_id](https://docs.godotengine.org/en/4.6/classes/class_os.html#get-unique-id)。
- Google 绑定使用标准 Google Sign-In/OpenID 作为游戏账号关联，不把 Play Games Player ID 直接当作游戏主账号；Google 官方将平台身份和游戏自己的账号体系分开，并建议跨设备连续性使用游戏自己的 Google 登录关联：[Platform authentication](https://developer.android.com/games/pgs/platform-authentication)。
- 命名校验、限流、异常记录停用和最低限度管理操作纳入服务；管理入口不嵌进游戏玩家流程。

## 6. 入口与返回行为

1. 主菜单左上角新增奖杯按钮和“排行榜”标签，与右上设置齿轮对称，三个模式主按钮保持原布局。首次从这里进入默认闯关页签，后续记忆上次选择。
2. 自由/经典结束页、闯关通关/失败页新增“查看排行榜”，直接打开本模式页签；当前主操作仍然是再来一局/下一关，不抢占主按钮。
3. 闯关选关页可增加同款小奖杯入口，打开闯关榜，不把排名塞进关卡塔格子。
4. 从结果页返回恢复该结果页；从选关页返回恢复选择和滚动位置；从菜单进入则返回菜单。排行榜本身不启动新局、不重置旧局。
5. 榜单底部“再来一局”跳转相应新局。闯关底部“继续闯关”返回选关页，选中最新已解锁关，仍由玩家点击开始；96 关全部完成时显示“重玩关卡”。

## 7. 最终视觉提案

主视觉沿用现有皇家蓝背景、浅蓝描边的立体面板、深靛蓝列表和绿色主按钮；页签按闯关金色、经典绿色、自由紫色区分。第一名居中略高，第二名左侧、第三名右侧，金银铜领奖台高度受控，列表仍是主要内容。

固定区自上而下为标题、三个模式页签、说明；中间排行榜内容垂直滚动；底部固定“我的排名”和模式操作。前三名是列表顶部内容，随列表滚走，避免小屏只剩装饰。查看我的排名无需一直滚到底。

设计尺寸以手机竖屏为主，1080×2340 参考；适配约 360dp 宽的小屏和安全区。Windows 居中显示同一面板，不把列表拉伸到整个横屏；支持鼠标滚轮、Tab、Enter、Esc。

- 顶部触控区不少于 48dp，列表每行至少 56dp；不是只有图标本身可点。
- 昵称过长优先省略，名次和分数不被挤掉；闯关两项成绩允许分两行。
- 所有 UI 文字通过已有 `L10n` 体系支持中、英、法。昵称是玩家内容，不随语言翻译；整数分组按语言展示，不把带逗号字符串作为服务端成绩。
- 动画只保留约 180–250ms 的开合/选中变化；减少动画关闭过渡和领奖台动效。榜单不持续闪烁、旋转或遮挡数字。

## 8. 数据和网络状态

| 状态 | 玩家看到的内容 | 操作 |
|---|---|---|
| 首次加载 | 行骨架或简短加载提示，模式页签和返回仍可用 | 返回 / 切换模式 |
| 设备 UID 初始化 | 生成本地设备账号和初始昵称“玩家4821”，不阻塞离线游戏 | 继续游戏 / 稍后绑定 |
| 已有成绩 | 真实前三、Top 100、固定我的名次 | 滚动 / 刷新 / 切换模式 |
| 空榜 | 服务已配置时由机器人补齐展示榜；未配置服务时显示离线演示榜并保留“重试”入口 | 开始对应模式 |
| 我的成绩为零 | “尚未上榜”，展示对应参榜条件 | 开始游戏 |
| 离线且有缓存 | “离线 · 显示上次排名”和上次更新时间，使用上次榜单 | 重试 / 继续游戏 |
| 离线且无缓存 | “暂时无法连接排行榜”，不伪装为空榜 | 重试 / 返回 |
| 新成绩待同步 | 保留上次认可的名次/成绩，另列新成绩“待同步” | 自动补传，不阻塞游戏 |
| Google 未绑定 | 设置显示“绑定 Google 账号”，解释可用于云端存档和换机恢复 | 玩家主动绑定 |
| Google 绑定冲突 | 对比本机与云端存档，不自动覆盖 | 使用本机 / 使用云端 / 取消 |
| Google 绑定成功 | 显示“云存档已同步”和更新时间 | 管理绑定 / 解除绑定 |
| 校验拒绝 | “这次成绩未计入排行榜”，本机游玩记录保留 | 再玩 / 查看规则 |
| 服务维护 | 明确维护提示，可保留上次榜单 | 重试 / 返回 |

榜单首批最多 100 条，按游标支持后续扩展；我的排名不在 Top 100 时由单独的个人查询显示，附前后各 2 名可在点击我的行时查看。短时间重复打开使用缓存，进入前台/主动重试触发有界刷新。返回、切换页签后，迟到请求不得覆盖新页面。

## 9. 服务方案和边界

推荐独立 HTTPS API + 持久数据库，Windows/Android 使用同一接口。Google 绑定使用标准 Google Sign-In/OpenID，云存档由本项目服务端保存；Google Play Games Saved Games 不作为本项目唯一存档来源。供应商、部署地区和费用在开发落地时确定，本次不创建云资源或付费服务。

服务职责：设备账号 UID、可选 Google OpenID 绑定、资料、历史迁移、云存档快照、对局/检查点接收、成绩验证、按模式查询、我的排名、真实玩家计数、管理停用记录。数据库负责每设备账号每模式唯一性、Google 绑定唯一性、闯关逐关最大分、幂等提交和排名顺序；机器人补位由带 `is_bot` 标记的展示数据或客户端展示层处理，不能混入真实玩家统计。

新对局依据服务端规则/配表版本和对局凭据校验，保存可核验的初始条件及合法落子序列，在可控验证任务中重算成绩与通关。仅 HTTP 加密、客户端签名或“分数范围正常”不能描述成完整反作弊。历史迁移按上一节的宽松信任边界处理。

关卡配额、计分或供块规则发生实质变化时，排行榜按 `ruleset_id` 分开；不把不同计分规则的成绩直接混入同一竞技榜。仅修改美术或文案不换榜。旧版迁移使用初次上线时公布的规则基线。

当前 APK/AAB 导出均为 `permissions/internet=false`，实际开发需启用网络权限。Godot 官方也明确 Android 未启用该权限会阻止网络通信：[Making HTTP requests](https://docs.godotengine.org/en/stable/tutorials/networking/http_request_class.html)。

## 10. 验收要求

- 三榜完全隔离；经典/自由只取最高分，闯关顺序与总分计算符合第 3 节。
- 旧记录导入一次且无损；重试、重复结算、重玩不会累计出虚假通关数/重复积分。
- 设备账号第一次打开即可生成本地 UID 和随机初始昵称；联网后可看榜，生成身份不打断离线游玩；换语言不改变成绩、设备账号 UID 或页签来源。Google 绑定必须由玩家主动点击设置按钮。
- 空榜、未上榜、离线、无缓存、补传、校验失败、维护可区分；同步中不显示虚构排名。
- 手机安全区、小屏及法语长文本可读；Windows 键鼠操作和结果/选关返回状态正确。
- 新对局验证与旧迁移记录来源可以区分；上线服务不可只返回演示数据。
- 必要静态/语法和逻辑测试由开发执行，实际界面、交互和声音依项目约定由用户验收。

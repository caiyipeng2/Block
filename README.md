# Block

Godot 4.7 的桌面方块消除游戏：拖动方块、填满行或列并消除，无时间限制。当前源码为 `0.6.3`，提供自由、经典和闯关三种模式，采用蓝色背景、凹槽棋盘和立体斜面方块。

项目仓库：[caiyipeng2/Block](https://github.com/caiyipeng2/Block)。本地交付、提交和推送状态以本次交付记录为准。

## 在 Godot 中运行

1. 使用 Godot 4.7 打开项目管理器，点击“导入”，选择项目根目录的 `project.godot`。当前开发使用 Godot 4.7.2 stable。
2. 打开项目后按 **F5**，进入主菜单；选择“自由模式”“经典模式”或“闯关模式”。闯关模式先进入选关页，再开始所选关卡。
3. 收集关自动展示目标、飞向 HUD，再显示棋盘；点击或按键可跳过介绍。完成后从下方托盘按住方块，拖到棋盘合法位置释放。

默认面向 Windows 桌面鼠标输入，渲染配置为 Forward Plus / D3D12。

## 玩法与操作

- 默认 8×8 棋盘，每轮三块，三块用完后才补充下一组。自由、经典和闯关前两关保持普通 3–5 格，前两关必要时可用 1–2 格教学救援；第 3 关起收集模式使用独立 2–9 格形状池，不影响公共形状配置。
- 方块不能旋转。只有整个形状在棋盘内且不与已有方块重叠时才能放置；非法释放会回弹到托盘，棋盘与分数不变。
- 完整行和完整列同时清除，交叉格只计一次；其他方块保持原位，不下落。
- 合法放置按实际格数 ×10 得基础分，清除另行加分，多线倍率只作用于清除分。3 格不清线得 30 分，补满一条 8 格行得 30+80=110 分；非法释放不加分。收集模式 Combo 默认容忍两次不清线的合法铺垫，第三次断连；其他模式沿用原规则。这是可配置实现，不声称复现竞品算法。
- 玩家可自由选择托盘中的方块；新的一组三块至少有一种放置顺序与落点组合，逐步落子、清线后能全部放完。普通模式与第 3 关起，玩家操作后所有剩余方块均无合法落点时结束本局；前两关使用下述教学推进规则。
- **Esc** 暂停/继续；常规游戏中的 **R** 请求重新开始。收集介绍期间点击/按键仅跳过介绍，不穿透棋盘。进行中的重开和返回菜单需要确认，Game Over 后可直接选择下一步。
- HUD、暂停和 Game Over 使用原生按钮，支持 **Tab** 切换焦点、**Enter/Space** 激活。棋盘落子/清除结算时锁定输入，宝石收集飞行可与下一次操作并行；暂停和继续仍可用。
- 设置提供音效、音乐、画面震动、减少动画和试听音效；自由/经典最高分、已通关关卡、关卡最佳分与设置保存到 `user://savegame.json`，本版不保存进行中的棋局。收集界面只保留返回与齿轮，齿轮打开暂停面板，再进入真实设置或选择重开/返回；计分明细移入暂停面板。

## 三种模式

| 模式 | 开局与目标 | 记录 |
|---|---|---|
| 自由模式 | 原有空棋盘玩法；积分不设上限 | 沿用旧版最高分 |
| 经典模式 | 开局随机预置约 16–24 格，留空格且没有满行/列；预置方块不计分；积分不设上限 | 独立最高分 |
| 闯关模式 | 默认 96 关；前两关分别 368、392 分；第 3 关起每关从四种标记中选三种，完成各类配额 | 逐关解锁、最高通关关卡及每关最佳分 |

闯关选关页采用从底部向上攀升的 **S 形藤蔓路线**，每 12 关设一段旅程平台。关卡格可见边长收紧到 32–42px，保留至少 44px 点击区域与约 76px 纵向节点间距；主藤、卷须和叶片使用多层明亮饱和绿，锁关只影响关卡格，不让整株植物灰暗。当前选中格上方有浮动金色菱锥；完成后返回地图，镜头向最新解锁关卡短距离上移，手动滚动可取消。新玩家只能开始第 1 关；过上一关才能点亮下一关，每次进入默认选择最新解锁关卡，已通过关卡可重玩。

前两关保持一体式分数进度 HUD。**第 3 关起从蓝钻、金宝、黄星、红星中每关选三种，每五关轮换省略类型**；各类需求归零即通关，目标配额不等于棋盘上的物理标记数量，富余标记可留在盘上。总配额第 3/4/5 关为 **24/30/36**，后续按阶梯提升，末关 **120**；新托盘持续携带尚未完成类型，允许需求只差 1 仍出现多枚，实际计入数量会封顶。物理清除仍按真实格数计分，高分不能代替配额完成。

收集开局自动按“目标展示约 1.0 秒 → 飞到 HUD 约 0.48 秒 → 填充/擦拭揭示棋盘约 0.70 秒”进入游戏，点击或按键可跳过，减少动画下延后到下一帧直接结束显示流程。介绍只影响显示，不送分、不消除；期间棋盘与背景焦点隔离。`Final Block` 只在真正完成目标的落子后出现，不提示应放位置。

**前两关用于引导并持续推进**：托盘优先提供利于清线的普通 3–5 格组合，并逐步构造整组完整可放路径。构造路线的每一步都在模拟棋盘上判断：普通块均无合法点才考虑 2 格，2 格也无合法点才用 1 格；所以一组中可能提前包含后续认证步骤所需的救援块。每次真实合法落子后，若剩余组没有完整路径，则在保留仍可用组合的前提下替换为同样数量的可解方块。救援不修改已落棋盘、不送分、不降低 368/392 分目标，也不直接通关；默认每次合法落子至少得到 10 分，因此持续进行合法操作可以推进至目标。该例外仅作用于闯关第 1、2 关，不放宽全局形状校验，也不改变第 3 关起、自由或经典的失败规则。

开局提供翼、心、环、阶梯、斜蝶五类图案及镜像。标记随方块从托盘、拖动/回弹、预览、落地到清除完整传递，每组仍须有完整可放证书；供块优先有限清线友好构造，失败后回退完整求解器。旧版“全部目标仅在初始棋盘、整关最多三轮认证”已取消，**不保证错摆必过或每关唯一**。详见 [三种模式说明](docs/Block-Blast-Godot-三种模式.md)。

## 第二阶段美术与反馈

- `0.6.3` 托盘改为所有槽位共用单格尺寸，按模式形状池包络预留高度；短条、长条和大方块仅分别居中，消费方块后也不变尺。绘制、命中、抓取与回弹使用同一几何，规则和胜利反馈不变。
- `0.6.2` 强化真正完成目标的最后落子：整块放大、抬起后快落回弹，接触粉紫光、双环、星点与棋盘边框扫光，再清除和收集；普通落子和旧块保持稳定。胜利改为暗场、三宝石大勾、`Well Done` 与绿色 `Next Level` 分阶段登场，尊重减少动画和震动开关。
- `0.6.1` 修复每次放置时旧方块随反馈接管/恢复而跳动：静态、预览、拖动和反馈共用格内几何，统一先空格后按行列画已占格。新落子自身弹性与正常清除震动保留，独立收集飞行和规则不变。
- `0.5.1` 重绘收集标记：短粗、浅凹口的六角红星与金橙五边形宝石，采用大中央面和柔和受光，去除白十字、大光晕和粗黑圈；棋盘、HUD、开局面板与飞行使用同款。普通目标格使用暖砂金专用底托，满线预览与清除继续整组统一主色，标记最后单独绘制。
- 深蓝渐变背景、藏蓝凹槽棋盘，蓝/橙/绿/紫/黄/青六色方块使用统一斜面材质；棋盘、托盘、拖动浮层和反馈层保持一致。
- 游戏区居中，大号青色当前分、金色皇冠最高分和原生图标按钮；托盘方块独立排列，菜单、设置、暂停和结束面板使用深蓝/金色主题。
- 即将消除的整行/列统一为占格数最多的颜色；平票按该线中最早放置的颜色，相交行列整组去重选色。预览与消除动画保持一致。托盘保持正常亮度，不提前提示可放性，非法释放后才反馈。
- 收集飞行独立管理，先弹大、外散，再吸入对应 HUD；每枚到达才更新展示数、闪光和完成绿勾。连续下一次落子不会删除旧批，暂停冻结，resize/减少动画结清，新局静默重置；通关面板等待最后一枚到达。收集关关闭 `+分` 浮字，真实积分继续累计，明细在暂停查看；物理标记超过剩余配额时仍展示真实清除，计入配额封顶。
- 收集界面托盘更小更紧凑、棋盘网格更弱，计分明细放入暂停。胜利显示大号 `Well Done`、目标绿勾、彩纸与绿色 `Next Level`；连胜系统和地图奖励本轮明确不做。
- 暂停、通关与失败弹窗使用约 0.18 秒淡入和 0.96→1 缩放；减少动画时即时显示。
- “画面震动”仅控制视觉上的棋盘轻震，不是 Windows 鼠标或手柄硬件震动；“减少动画”关闭粒子、分数飞行与震动。

第二阶段美术沿用当时的基线，当前收集规则以上方三种模式为准。用户已提供 **`20261015-121221.mp4`（112.7 秒）**，本轮已审阅完整时间线和关键 0.1–0.25 秒片段，按确认条目实现目标、开场、飞行与胜利反馈；不声称逐帧完全复制，竞品音效和内部算法仍未知。参考中的 `+1` 不替换本项目每格 ×10 的真实计分。历史美术方向见 [美术优化说明](docs/Block-Blast-Godot-美术优化.md)。

## 配置入口

默认规则资源为 [`config/default_rules.tres`](config/default_rules.tres)，类型定义在 [`scripts/rules/game_rules_config.gd`](scripts/rules/game_rules_config.gd)。可在 Godot Inspector 中编辑棋盘尺寸、托盘数量、形状池及方向、计分、生成重试次数、色板/主题和动画时长。统一美术绘制入口为 [`scripts/ui/block_art.gd`](scripts/ui/block_art.gd)。模式目录、默认关数、目标类型与数量的统一入口为 [`scripts/modes/mode_catalog.gd`](scripts/modes/mode_catalog.gd)，选关文案与 HUD 使用同一目标配置。

默认配置对应已确认的 MVP。调整参数后需按目标玩法重新验收，不能沿用默认配置的结论。

规则层位于 `scripts/rules/`。生成器最近一轮的 `last_solution` 记录完整放置顺序，每步包含原始 `piece_index` 与棋盘 `origin`；`last_diagnostics` 记录 `seed`、`round`、`attempts`、`fallback_used`、`reason`、`nodes_elapsed`、`duplicate_candidates` 与 `elapsed_ms`，用于复现生成问题和调参。

## Windows 导出与打包

安装 **Python 3.10 或更新版本**及与当前 Godot **4.7.2 stable** 匹配的导出模板后，在项目根目录运行（将引擎路径换为本机实际路径）：

```powershell
python tools/export_windows.py --godot "E:\Tools\Godot\Godot_v4.7.2-stable_win64.exe" --configuration release
```

加 `--check` 仅预检、不导出；`--configuration debug` 生成调试包。版本号来自 `project.godot`，当前源码为 `0.6.3`，后续发布输出遵循 `dist/Block-<版本>-windows-x86_64-release.zip`。须完整解压后按 `START-HERE.txt` 运行，保留 `.pck` 和所有随附文件；若导出生成 DLL 或 `x86_64` 子目录，也须完整保留。包内 `build-info.json` 含文件 SHA256，ZIP 旁 `.sha256` 用于核对压缩包。

前一阶段的 `0.1.0` release/debug 包已导出，文件 SHA256、ZIP CRC 与压缩包校验值均匹配，独立 EXE 尚待用户验收。本地已有 `build/`、`dist/` 中的 `0.1.0` 包仍是粉色逻辑基线，**不含当前美术与三种模式**；本轮不重新打包 `0.6.3`，先按 F5 验收源码。当前本机使用已校验的 `work/release-templates/4.7.2.stable` 模板，将来重新打包时追加 `--templates-dir "work/release-templates/4.7.2.stable"`。模板安装、包结构和用户验收步骤见 [Windows 发布说明](docs/Block-Blast-Godot-Windows发布.md)，历史检查证据见 [验收记录](docs/Block-Blast-Godot-验收记录.md)。

# Block

Godot 4.7 的方块消除游戏：拖动方块、填满行或列并消除，无时间限制。当前源码为 `0.9.5`，提供自由、经典和闯关三种模式，采用蓝色背景、凹槽棋盘和立体斜面方块，支持Windows与Android。

`0.9.5` 去掉闯关消除提示背后的矩形灰底：文字下的半透明彩带强度不随档位变化、单线与四线一样重，金紫顶点插值后发灰。现在两种模式共用三层极淡同心柔光，档位轻重改由射线与星片数量表达，字形阴影与单线描边同步减淡。文案、阈值、时长、避让与全部玩法规则不变。

`0.9.4` 按参考视频把多线消除的彩色加强：按真实线数分档，消界线之间画约 0.17 格宽的贯穿彩虹带，格内彩色烧成高热近白块，外晕最高约 2.35 倍、白色闪点最多 10 个；多线的彩带与光晕在棋盘恢复后仍沿既有 0.52 秒强调层淡出，输入锁时长、规则、计分与收集都不变，单行保持 0.9.3 的轻量档。

`0.9.3` 把“看上去要收集多少”和“实际有多难”拆开：收集关显示总配额拉开到 28–140，目标种类 2–4 轮换，初始标记随配额缩放；真正的关卡长度改由新列 `marker_rounds`（标记供给时长）控制，并按 phase 给默认值。96 关曲线用无界面模拟重新校准，通过率偏差全部落在 ±15pp 内。同时按参考视频优化表现：50%/90% 进度改为横向飘过的横幅，消除后的即时反馈、特殊图案光效整体减重。配表与快照见[关卡配表说明](docs/Block-Blast-Godot-关卡配表说明.md)。

`0.9.2` 恢复闯关清线的即时赞语：分数教学关和收集关的首次单线都会显示 `Nice! / 1 Line`，2/3/4 线继续显示 Perfect / Excellent / Unbelievable 与真实线数；自由/经典保留原有的星爆光环和更长节奏。规则、计分、Combo、收集飞行、Final Block 与减少动画行为不变。

`0.9.1` 按 10 关周期重做 96 关难度曲线，新增形状档、额外初始方块、近胜密度与随机度四个杠杆，并用无界面模拟逐关校准。配表、模板和逐关快照见[关卡配表说明](docs/Block-Blast-Godot-关卡配表说明.md)。

`0.9.0` 新增设置中的语言切换：中文、English、Français，立即生效并自动保存。菜单、选关、三模式HUD、目标介绍、暂停/结算/确认框、连击及进度漂字共用[翻译词典](assets/localization/messages.json)。扩展和验证方式见[多语言说明](docs/Block-Blast-Godot-多语言.md)。

## 在 Godot 中运行

1. 使用 Godot 4.7 打开项目管理器，点击“导入”，选择项目根目录的 `project.godot`。当前开发使用 Godot 4.7.2 stable。
2. 打开项目后按 **F5**，首次启动播放约 3.60 秒开屏后进入主菜单；点击或按 Enter/Space/Esc 可跳过，减少动画时直接显示菜单。选择“自由模式”“经典模式”或“闯关模式”；闯关先进入选关页，再开始所选关卡。返回主菜单不重播开屏。
3. 收集关自动展示目标、飞向 HUD，再显示棋盘；点击或按键可跳过介绍。完成后从下方托盘按住方块，拖到棋盘合法位置释放。

默认面向 Windows 桌面鼠标输入，渲染配置为 Forward Plus / D3D12。

`0.8.9` 调整手机选关页：居中标题、较小返回箭头、立体悬浮菱锥及紧凑塔形地图，移除标识底部阴影；奖杯从暗色随真实通关进度逐步点亮。通关条件只在关卡内展示。沿用 `0.8.8` 开屏与模式菜单及 `0.8.7` 设置弹窗。最终包与记录见 [Android发布](docs/Block-Blast-Godot-Android发布.md)，包名、原创图标、签名及用户存档保持。

## 玩法与操作

- 默认 8×8 棋盘，每轮三块，三块用完后才补充下一组。自由、经典和闯关前两关保持普通 3–5 格，前两关必要时可用 1–2 格教学救援；第 3 关起收集模式使用独立 2–9 格形状池，不影响公共形状配置。
- 方块不能旋转。只有整个形状在棋盘内且不与已有方块重叠时才能放置；非法释放会回弹到托盘，棋盘与分数不变。
- 完整行和完整列同时清除，交叉格只计一次；其他方块保持原位，不下落。
- 合法放置按实际格数 ×10 得基础分，清除另行加分，多线倍率只作用于清除分。3 格不清线得 30 分，补满一条 8 格行得 30+80=110 分；非法释放不加分。收集模式 Combo 默认容忍两次不清线的合法铺垫，第三次断连；其他模式沿用原规则。这是可配置实现，不声称复现竞品算法。
- 玩家可自由选择托盘中的方块；新的一组三块至少有一种放置顺序与落点组合，逐步落子、清线后能全部放完。普通模式与第 3 关起，玩家操作后所有剩余方块均无合法落点时结束本局；前两关使用下述教学推进规则。
- 自由/经典当前分数低于 1500 时，新开局和补充新组三块会优先选择能即时单/多线、连续清除或利于铺垫的组合，仍只用原普通形状。达到 1500 后下一组恢复原供块，已经发出的块不替换；不承诺每手必清或任意错摆必过。积分与严格断连规则不变。
- **Esc** 暂停/继续；常规游戏中的 **R** 请求重新开始。收集介绍期间点击/按键仅跳过介绍，不穿透棋盘。进行中的重开和返回菜单需要确认，Game Over 后可直接选择下一步。
- HUD、暂停和 Game Over 使用原生按钮，支持 **Tab** 切换焦点、**Enter/Space** 激活。棋盘落子/清除结算时锁定输入，宝石收集飞行可与下一次操作并行；暂停和继续仍可用。
- 设置提供音效、音乐、画面震动、减少动画和试听音效；自由/经典最高分、已通关关卡、关卡最佳分、逐关失败次数与设置保存到 `user://savegame.json`，本版不保存进行中的棋局。齿轮直接打开设置弹窗并暂停当前局，可继续、重开或返回；关闭恢复进入前状态。退出应用也会先确认，取消不退出。

## 三种模式

| 模式 | 开局与目标 | 记录 |
|---|---|---|
| 自由模式 | 原有空棋盘玩法；积分不设上限 | 沿用旧版最高分 |
| 经典模式 | 开局随机预置约 16–24 格，留空格且没有满行/列；预置方块不计分；积分不设上限 | 独立最高分 |
| 闯关模式 | 96 关逐行读 CSV；前两关为分数目标，第 3 关起完成表中启用的 1–4 类收集配额 | 逐关解锁、最高通关关卡及每关最佳分 |

闯关选关页恢复最初的 **不规则方格塔**：从底向上逐排编号，常规窗口最多 11 列、默认 96 关共 13 行，窄窗口减少列数。关卡按钮边长上限 36px，格面约 32px，格距 4px；移除藤蔓、卷须、叶片与旅程平台。选中格保留缩小的金色菱锥，贴近上边缘且不遮上排关号；已通过青色、选中金色、锁定藏蓝。新玩家只能开始第 1 关，逐关解锁，每次进入默认选择最新解锁关卡；旧关可重玩，目标摘要、保存失败提示和可取消的自动定位继续保留。

通关后点击 **Next Level／下一关** 先返回选关页，不直接开新局。真实通关首次提高解锁上限时，播放约 2.20 秒的“完成横带 → 青色方块归位旧关 → 新关金色点亮与菱锥跃迁”，再由玩家点击开始新关。进度在通关时立即保存；重启旧档、重玩已过关、失败与末关不误播。返回、开始、另选关卡、手动滚动或窗口变化会收起演出并恢复最终状态，不重播；减少动画直接显示结果。

前两关保持一体式分数进度 HUD。**第 3 关起，蓝钻、金宝、黄星、红星的需求数量分别读取配置表，0 表示该关不参与**；各类需求归零即通关，目标配额不等于棋盘上的物理标记数量，富余标记可留在盘上。目标可逐关修改，不按关号自动增长或强制四选三轮换；当前保留用户调整后的第 3 关 **40/29/15（共 84）**、第 4 关 **30/25/20（共 75）**，实际类型和数量以 CSV 为准。新托盘持续携带尚未完成类型，允许需求只差 1 仍出现多枚，实际计入数量会封顶。物理清除仍按真实格数计分，高分不能代替配额完成。

收集开局自动按“目标展示约 1.0 秒 → 飞到 HUD 约 0.48 秒 → 填充/擦拭揭示棋盘约 0.70 秒”进入游戏，点击或按键可跳过，减少动画下延后到下一帧直接结束显示流程。介绍只影响显示，不送分、不消除；期间棋盘与背景焦点隔离。`Final Block` 只在真正完成目标的落子后出现，不提示应放位置。

**前两关用于引导并持续推进**：托盘优先提供利于清线的普通 3–5 格组合，并逐步构造整组完整可放路径。构造路线的每一步都在模拟棋盘上判断：普通块均无合法点才考虑 2 格，2 格也无合法点才用 1 格；所以一组中可能提前包含后续认证步骤所需的救援块。每次真实合法落子后，若剩余组没有完整路径，则在保留仍可用组合的前提下替换为同样数量的可解方块。救援不修改已落棋盘、不送分、不降低 368/392 分目标，也不直接通关；默认每次合法落子至少得到 10 分，因此持续进行合法操作可以推进至目标。该例外仅作用于闯关第 1、2 关，不放宽全局形状校验，也不改变第 3 关起、自由或经典的失败规则。

开局提供翼、心、环、阶梯、斜蝶五类图案及镜像。标记随方块从托盘、拖动/回弹、预览、落地到清除完整传递，每组仍须有完整可放证书；供块优先有限清线友好构造，失败后回退完整求解器。旧版“全部目标仅在初始棋盘、整关最多三轮认证”已取消，**不保证错摆必过或每关唯一**。详见 [三种模式说明](docs/Block-Blast-Godot-三种模式.md)。

**失败重试辅助**：仅已合法落子后出现 Game Over 才累计本关失败，主动重开/退出/暂停不计；记录持久化，通过后清除本关记录。第 3 关起下一次新开/重开按表中 `retry_assist_step` / `retry_assist_max` 生成更容易清掉尚缺目标、保留空间的方块，默认强度为 20% → 40% → 60% 封顶，不代表通过率。目标和计分不降低，当前剩余块不替换，仍可能失败；前两关维持原教学救援，自由/经典不受影响。当前局参数固定，界面不提示降难度。

## 配置入口

闯关参数的唯一来源为 [`config/adventure_levels.csv`](config/adventure_levels.csv)，可用 Excel/WPS 编辑并保存为 **UTF-8、逗号分隔 CSV**。每行一关，现版必须完整保留连续的 1–96 关；四类目标可分别设为 0–999，`difficulty` 为 0–100，可填小数，支持高低交替，不要求递增。完整字段、模板和示例见 [关卡配表说明](docs/Block-Blast-Godot-关卡配表说明.md)。当前不能仅追加第 97 行扩关。

当前表末尾新增 `retry_assist_step` / `retry_assist_max`，均为 0–100，可小数，默认 `20/60`；任一设 0 可关闭该关新增辅助。例如 `10/40` 表示每次失败增加 10%、最多 40% 的生成辅助。旧 15 列表缺少这两列时使用默认值，列存在但空白则报错；其余原始参数保留。

进入选关、开始新局和重开时重新读取；进行中棋局不随文件变化。编码必须是 UTF-8（可带 BOM）；普通“CSV（逗号分隔）”可能被 Excel/WPS 保存为 GBK/GB18030，应选择“CSV UTF-8”。编码、表头、数字、范围、漏关/重复关、非法模板等异常会显示 CSV 路径和原因，整表拒绝闯关，不清空已有局，也不回退旧公式；自由/经典仍可正常进入。模板不适配自定义棋盘时会拒绝该局。配置难度只调整候选倾向，不保证唯一解或整关必胜。

默认公共规则资源为 [`config/default_rules.tres`](config/default_rules.tres)，类型定义在 [`scripts/rules/game_rules_config.gd`](scripts/rules/game_rules_config.gd)。可在 Godot Inspector 中编辑棋盘尺寸、托盘数量、形状池及方向、计分、生成重试次数、色板/主题和动画时长。统一美术绘制入口为 [`scripts/ui/block_art.gd`](scripts/ui/block_art.gd)。[`scripts/modes/adventure_level_table.gd`](scripts/modes/adventure_level_table.gd) 负责读表校验，[`scripts/modes/mode_catalog.gd`](scripts/modes/mode_catalog.gd) 向选关文案、HUD 和生成器提供同一份关卡数据。

默认配置对应已确认的 MVP。调整参数后需按目标玩法重新验收，不能沿用默认配置的结论。

规则层位于 `scripts/rules/`。生成器最近一轮的 `last_solution` 记录完整放置顺序，每步包含原始 `piece_index` 与棋盘 `origin`；`last_diagnostics` 记录 `seed`、`round`、`attempts`、`fallback_used`、`reason`、`nodes_elapsed`、`duplicate_candidates` 与 `elapsed_ms`，用于复现生成问题和调参。

## Windows 导出与打包

安装 **Python 3.10 或更新版本**及与当前 Godot **4.7.2 stable** 匹配的导出模板后，在项目根目录运行（将引擎路径换为本机实际路径）：

```powershell
python tools/export_windows.py --godot "E:\Tools\Godot\Godot_v4.7.2-stable_win64.exe" --configuration release
```

加 `--check` 仅预检、不导出；`--configuration debug` 生成调试包。版本号来自 `project.godot`，当前源码为 `0.8.3`，后续发布输出遵循 `dist/Block-<版本>-windows-x86_64-release.zip`。CSV 已设置为保留原文导入，并由导出包含规则带入 `.pck`；源码改表后需重新导出才能更新玩家包。须完整解压后按 `START-HERE.txt` 运行，保留 `.pck` 和所有随附文件；若导出生成 DLL 或 `x86_64` 子目录，也须完整保留。包内 `build-info.json` 含文件 SHA256，ZIP 旁 `.sha256` 用于核对压缩包。

历史Windows `0.1.0` ZIP和解包目录已按两版保留策略清理，导出步骤与历史证据保留；当前尚未生成Windows新包。Android仅保留 `0.8.9` 与 `0.8.8` 的APK/AAB和对应校验记录。本机模板 `work/release-templates/4.7.2.stable` 继续保留，重新打包Windows时追加 `--templates-dir "work/release-templates/4.7.2.stable"`。模板与后续打包方法见 [Windows 发布说明](docs/Block-Blast-Godot-Windows发布.md)。
